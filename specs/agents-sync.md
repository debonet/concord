# agents-sync: generating Claude Code's agent files

## Purpose

`agents-sync` writes Claude Code's agent file for each Concord role from the
role's text and its Claude Code frontmatter.

## API

* {#s-n7q049 <arch} **Form.** `~/@concord/bin/agents-sync [--dir <path>]
  [--roles <path>] [--force]` takes each option at most once, in any order.
  {#s-xszaj3 <arch} Given any other argument, an option twice, or `--dir` or
  `--roles` with no path after it, it writes nothing, prints its usage line
  to stderr and exits 2.
* {#s-dvkjf9 <arch} **No project.** It acts on no adopting project: it reads no
  `concord.json`, and its working directory matters only to resolve a
  relative path given to `--dir` or `--roles`.
* {#s-z7h1uz <arch} **Roles.** It reads the roles from the `roles/` directory of
  the Concord project its own file belongs to, whatever its working
  directory, or from the directory `--roles` names. {#s-odwk2n <arch} A role is a
  name `<role>` for which that directory holds both `<role>.md`, the role
  text, and `<role>.claude-frontmatter`, Claude Code's frontmatter for it.
* {#s-bd1fn4 <arch} **Incomplete roles.** When the roles directory does not
  exist, holds no role, or holds a `.md` file with no `.claude-frontmatter`
  file of the same name beside it or the reverse, it prints to stderr one
  line naming the problem, writes nothing and exits 2.
* {#s-svb3n9 <arch} **Target directory.** It writes into the directory `--dir`
  names, or into `$HOME/.claude/agents` when `--dir` is absent.
  {#s-1kulh7 <arch} A target directory that does not exist makes it print to
  stderr one line naming it, write nothing and exit 2.

## The agent file

* {#s-q4dp5b <arch} **Byte for byte.** For each role it writes
  `<role>.md` in the target directory holding the bytes of
  `<role>.claude-frontmatter` followed directly by the bytes of the role's
  `<role>.md`, with nothing inserted, removed or converted.
* {#s-2p939f <arch} **Nothing else.** It writes no file but the roles' agent
  files and its record file, each directly in the target directory, and
  nothing outside the target directory; it deletes nothing and leaves every
  other file there, an agent file of a name no role has among them, as it
  was.
* {#s-3qwypa <arch} **Output.** On success it prints one line per role on
  stdout, in role-name order, `wrote <path>` when it wrote the agent file
  and `unchanged <path>` when the file already held the generated bytes,
  `<path>` being the target directory as given, or `$HOME/.claude/agents`
  with `$HOME` expanded, joined with the file name; and exits 0.

## Detecting a hand edit

* {#s-utqlgq <arch} **The record file.** The record file is
  `.concord-agents-sync.json` in the target directory: one JSON object
  mapping the name of each agent file `agents-sync` wrote there to the
  lowercase hexadecimal SHA-256 of the bytes it wrote. {#s-ct9wos <arch} After a
  run that exits 0 it holds, for each role, the hash of that role's agent
  file as it then stands, and every entry for a name no role has as it was.
* {#s-j4tine <arch} **Hand-edited.** An agent file that exists is hand-edited
  when its bytes differ from the bytes this run would write and their
  SHA-256 differs from the hash the record file holds for its name, or the
  record file holds none; a file `agents-sync` wrote that nobody has
  changed since is not hand-edited.
* {#s-h1qxdb <arch} **Refusal.** Without `--force`, when any role's agent file
  is hand-edited, it prints to stderr one line per such file, naming its
  path and saying the file was edited since it was generated and that
  `--force` overwrites it; writes nothing, the record file included; and
  exits 2. {#s-gim8db <arch} With `--force` it writes every role's agent file,
  hand-edited or not.
* {#s-0woned <arch} **A bad record file.** A record file that is not one JSON
  object whose every value is 64 lowercase hexadecimal characters makes it
  print to stderr one line naming the file, write nothing and exit 2;
  {#s-lx979r <arch} with `--force` it replaces such a record file with one
  holding only the roles' entries.

## Dependencies

* {#p-xdrt3v >specs/concord-process.md#agent-instructions} The role texts, their
  Claude Code frontmatter, and the rule that a generated agent file is
  never edited by hand.

## Error Handling

Errors reach the caller as exit code 2 and one stderr line each, as above;
on any error it writes nothing.
