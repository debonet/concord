# agents-sync: generating agent files

Statement ids: complete

## Purpose


`agents-sync` writes every agent-tool file Concord generates from its roles
and writes nothing that is already current.

* {#s-yf8wyo <m-mzt14m@7dbb5d4} **Every tool, one run.** Every run regenerates every file
  Concord generates for any agent tool; it takes no option naming a tool,
  and what it writes and prints does not depend on which agent tool's
  session runs it.

## API

* {#s-n7q049 <arch} **Form.** `concord agents-sync [--dir <path>]
  [--roles <path>] [--force]` takes each option at most once, in any order.
  {#s-xszaj3 <arch} Given any other argument, an option twice, or `--dir` or
  `--roles` with no path after it, it writes nothing, prints its usage line
  to stderr and exits 2.
* {#s-dvkjf9 <arch} **No project.** It acts on no adopting project: it reads no
  `concord.json`, and its working directory matters only to resolve a
  relative path given to `--dir` or `--roles`.
* {#s-z7h1uz <arch} **Roles.** It reads the roles from the `roles/` directory of
  the Concord project its own file belongs to, whatever its working
  directory, or from the directory `--roles` names. A role is a name
  `<role>` for which that directory holds `<role>.md`, the role text, and
  metadata files for every generated agent-tool format.
* {#s-npmw3x <arch} **Incomplete roles.** When the roles directory does not
  exist, holds no role, or any role lacks metadata for a generated format,
  it prints to stderr one line naming the problem, writes nothing and exits 2.
* {#s-pite2d <m-mzt14m@7dbb5d4} **Targets.** Claude Code files go in `--dir` when given, or
  `$HOME/.claude/agents` otherwise. Codex files go in `--dir` when given,
  or `$CODEX_HOME/agents` when `CODEX_HOME` is set, or `$HOME/.codex/agents`
  otherwise. It creates a required target directory when it does not exist.

## The agent file

* {#s-jlo94e <arch} **Claude files.** For each role it writes `<role>.md` in the
  Claude target directory, holding the bytes of `<role>.claude-frontmatter`
  followed directly by the bytes of the role's `<role>.md`.
* {#s-ab1xqm <arch} **Codex files.** For each role it writes `<role>.toml` in the
  Codex target directory. The TOML metadata in `<role>.codex-frontmatter`
  supplies its `name` and `description`, and its `developer_instructions`
  value is the complete role text encoded as a TOML string. The generated
  TOML is a standalone Codex custom-agent definition.
* {#s-7ul58j <arch} **Nothing else.** It writes no file but the generated agent
  files and its record file, directly in their respective target
  directories, and nothing outside those directories; it deletes nothing
  and leaves every other file there as it was.
* {#s-jmhct4 <arch} **Output.** On success it prints one line per generated file
  on stdout, ordered by role name and then format, `wrote <path>` when it
  wrote the file and `unchanged <path>` when the file already held the
  generated bytes; paths use the target directory and file name, and the
  command exits 0.

## When nothing changed

* {#s-sjq95s <m-uk0okl@a350656,m-ckynhd@8e6b53f} **Up to date.** A run is up to date when every role's
  agent file in the target directory already holds the bytes the run would
  write it and the record file already holds the text the run would write
  it.
* {#s-i062i7 <m-uk0okl@a350656,m-ckynhd@8e6b53f} **An up-to-date run does no work.** An up-to-date run
  opens no file for writing, creates, deletes and renames no file, changes no
  file's bytes or modification time, prints `unchanged <path>` for each role
  as Output gives, and exits 0.
* {#s-4gru26 <m-uk0okl@a350656,m-ckynhd@8e6b53f} **No write access needed.** An up-to-date run does so,
  and exits 0, when the target directory and every file in it deny writing.
* {#s-8e60a5 <m-uk0okl@a350656,m-ckynhd@8e6b53f} **Only what differs is written.** A run that is not
  refused writes an agent file only when it does not exist or its bytes
  differ from the bytes the run would write it, and writes the record file
  only when it does not exist or its text differs from the text the run
  would write it; every other file keeps its bytes and its modification
  time.
* {#s-cmdkv2 <arch} **Record text fixed by its entries.** The text a run writes
  to the record file depends only on the set of entries it holds, so a run
  that follows a run that exited 0, with no file in the roles directory or
  the target directory changed between them, is up to date.
* {#s-d9mhcc <arch} **Record last.** A run writes the record file after every
  agent file it writes.
* {#s-i1uuvg <arch} **A failed write.** When a needed write is refused by the
  system or otherwise fails, it prints to stderr one line naming the file's
  path, saying a write was needed and could not be made and that
  `agents-sync` must be run where the target directory is writable, and
  exits 3. {#s-aqxbjg <arch} No other outcome exits 3, so a failed write is told
  apart from a usage error, a bad roles or record file and a hand-edit
  refusal, which exit 2. {#s-tgbh92 <arch} After a failed write, every file the
  run had not begun to write is as it was.

## Detecting a hand edit

* {#s-utqlgq <arch} **The record file.** Each target directory has a
  `.concord-agents-sync.json` record file: one JSON object mapping the name
  of each agent file `agents-sync` wrote in that directory to the lowercase
  hexadecimal SHA-256 of the bytes it wrote. {#s-ct9wos <arch} After a run that
  exits 0 each record file holds the hashes of the generated files in its
  directory, and every entry for a name no role has as it was.
* {#s-j4tine <arch} **Hand-edited.** An agent file that exists is hand-edited
  when its bytes differ from the bytes this run would write and their
  SHA-256 differs from the hash the record file holds for its name, or the
  record file holds none; a file `agents-sync` wrote that nobody has
  changed since is not hand-edited.
* {#s-kn4es1 <m-32ur2f@de576ec} **No record file.** A target directory with no record
  file is read as a record file with no entries: an existing agent file
  whose bytes differ from the bytes the run would write is hand-edited, and
  one whose bytes equal them is not.
* {#s-h1qxdb <arch} **Refusal.** Without `--force`, when any role's agent file
  is hand-edited, it prints to stderr one line per such file, naming its
  path and saying the file was edited since it was generated and that
  `--force` overwrites it; writes nothing, the record file included; and
  exits 2. {#s-gim8db <arch} With `--force` it writes every role's agent file,
  hand-edited or not.
* {#s-0woned <arch} **A bad record file.** A record file that is not one JSON
  object whose every value is 64 lowercase hexadecimal characters makes it
  print to stderr one line naming the file, write nothing and exit 2;
  {#s-lx979r <arch} with `--force` it replaces such a record file with one
  holding only the roles' entries.

## Dependencies

* {#p-shlwl6 >specs/concord-process.md#agent-instructions} The role texts, each
  tool's metadata, and the rule that a generated agent file is never edited
  by hand.

## Error Handling

* {#s-048ffy <arch} An error found before any write (a usage error, missing or incomplete
roles, a bad record file, a hand-edit refusal) reaches the caller as exit
code 2 and one stderr line each, as above, and the run writes nothing. A
directory creation or file write that fails reaches the caller as exit code
3, as A failed write gives.
